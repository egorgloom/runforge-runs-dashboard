#### Отчет об использовании AI (AI_LOG)

#### Использованные инструменты

- **Инструмент:** GitHub Copilot (включая Copilot Chat в VS Code).
- **Модель:** GPT-4o.
- **Роль AI:** Автодополнение кода, генерация boilerplate-компонентов, написание CSS-модулей и интеграционных тестов.

#### Примеры запросов, которые помогли в решении

В работе с Copilot Chat я использовал промпты с контекстом открытых файлов (типы Run и структура App.tsx). 

1. **Архитектура состояния:**
   _Запрос:_ «Напиши кастомный хук useRuns, который делает запрос к API, обрабатывает состояния загрузки и ошибки, а также фильтрует массив по статусу и поисковой строке. Добавь синхронизацию фильтров с URL (без react-router)».
   _Результат:_ Copilot сгенерировал хук с использованием window.history.replaceState и URLSearchParams.
2. **Адаптивная верстка:**
   _Запрос:_ В файле RunCard.tsx я написал комментарий // CSS for card: desktop row, mobile column from 360px и вызвал Copilot Chat.
   _Результат:_ Получен CSS-модуль с медиа-запросами и использованием CSS-переменных.
3. **Интеграционные тесты:**
   _Запрос:_ «Напиши тесты на Vitest + React Testing Library для проверки фильтрации, поиска и открытия модального окна. Используй мок-данные».
   _Результат:_ Был сгенерирован каркас тестов.

#### Ошибки и недочеты, предложенные AI

При генерации тестов Copilot предложил код, который успешно проходил по одному (если запускать тест изолированно), но **падал при последовательном запуске всего набора**. 

**В чем была проблема:**
Copilot не учел, что в приложении реализована синхронизация фильтров с URL. Первый тест кликал на фильтр «Running» и записывал ?status=running в window.location. При запуске следующего теста состояние URL в jsdom не сбрасывалось, и приложение инициализировалось со старым активным фильтром, из-за чего поиск не находил нужные карточки. 

**Как я это заметил и исправил:**
Я проанализировал HTML-вывод ошибки от Testing Library в терминале, где было видно, что кнопка фильтра «Running» все еще активна (aria-pressed="true"), а карточки с другими статусами отфильтрованы. 

Решением стало добавление двух вещей: 

1. В beforeEach тестов я добавил сброс URL: window.history.replaceState({}, '', '/').
2. В файл настройки тестов tests/setup.ts я добавил вызов cleanup() из Testing Library для гарантированного размонтирования компонентов после каждого теста.

После этих правок все 7 интеграционных тестов стали проходить стабильно.
